# 无限地图 + 模型池 + 虚假记忆 实现计划

## Context

v2.0.0 呈现层交付完毕后，计划书中三个核心缺口仍待补齐：

1. **无限地图**——计划书第二章 1-4 节（区块 64×64 / 四层精度 / 冷热系统 / 无限制视野），现状是 72×72 固定数组
2. **模型池**——计划书第十三章（多模型加减 / NPC 分配 / 故障链 / 小镇语感），现状是单套 AI 配置
3. **虚假记忆**——计划书第三章第七节五类记忆中的第五类（"坚信发生过、其实没发生过"），现状只实现了四类

三者的依赖关系：无限地图是地基（NPC 能走到远方才有外部世界），模型池是居民大脑（多声音），虚假记忆是记忆系统最后一块拼图。按优先级分三步交付。

***

## 第一步：无限地图（v2.1.0）

### 新文件 `chunk.js`

```
chunk.js 导出：
  常量: CHUNK=64, CHUNK_AREA=4096, ST{VIRGIN:0,COLD:1,COOL:2,WARM:3,HOT:4}
  坐标转换: chunkKeyOf(tx,ty)→{cx,cy,lx,ly}, worldToChunk(tx,ty)→[cx,cy], chunkOrigin(cx,cy)→{x0,y0}, localIdx(lx,ly)→0..4095
  种子派生: chunkSeed(worldSeed,cx,cy)→uint32  // 确定性哈希
  区块生成: genChunk(worldSeed,cx,cy,opt)→chunk  // opt.originGen 回调注入城镇生成
  野外生成: genWildChunk(chunk,worldSeed)  // 草地/河流/树林/矿物/野花，用 hash2+sin 噪声，不引第三方库
  起源判定: isOriginChunk(cx,cy)→bool  // cx∈{0,1} cy∈{0,1}
  WorkingSet 类:
    constructor(worldSeed, opt)
    get(cx,cy)→chunk|null  // 只读，不生成
    getOrGen(cx,cy)→chunk  // VIRGIN→COLD
    ensure(cx,cy)→chunk    // 同上，语义"我要操作它"
    drop(cx,cy)             // 驱逐
    has(cx,cy)→bool
    iterNonVirgin()→Iterator  // 遍历所有非 VIRGIN chunk
    forEachHot(fn) / forEachWarm(fn) / forEachCool(fn)
    evictIfNeeded()         // 容量超限时 LRU 驱逐
  tile 访问: tileGroundAt(ws,tx,ty)→G.*, tileObjAt(ws,tx,ty)→O.*
  状态机: promoteToHot(ws,cx,cy,clock), promoteToWarm, coolDown, freeze
  序列化: serializeChunks(ws)→Array, hydrateChunks(ws,data)
  chunk tick: tickChunkWarm(c,ctx,dtMin)  // 逐小时：作物缓长/房屋磨损/树桩回生
              tickChunkCool(c,ctx,dayDelta)  // 逐天：作物成熟/房屋磨损累积/树桩回生/矿区回生
```

### `core.js` 改动

保留 `MAP_W=72/MAP_H=72/idx/inB`（起源区块本地索引用，旧代码兼容），新增：

* `export const CHUNK = 64`

* `export function worldHash(worldSeed, tx, ty)` — 单点世界坐标哈希

### `world.js` 改动

**world 对象结构变**：`ground/obj` 两大数组不再存在，改为 `ws: WorkingSet`。`houses` 保留为起源区块房屋全集（NPC 初始化要用）。

* `genWorld(seed)` → 创建 WorkingSet，`ensure(0,0)/(1,0)/(0,1)/(1,1)` 生成起源 4 chunk，收集 houses

* `genOriginArea(chunk, worldSeed)` — 原 genWorld 函数体提取，按 chunk 坐标范围分片写入

* `walkable(w,x,y)` → `w.ws.get(x>>6,y>>6)` 取 chunk，读 `c.ground[localIdx]`，未持有返回 false

* `findPath(w,sx,sy,tx,ty)` → BFS 用 Map 存 seen/prev（不预分配大数组），maxExplore 默认 4096

* `placeObj/removeObj/setGround` → `w.ws.ensure(cx,cy)` + `c.dirty=true`

* `walkable/placeObj` 等的 `inB()` 边界检查改为"chunk 是否已生成"

* `regrowStumps/growCropsDaily` → 遍历 `ws.iterNonVirgin()` 中 WARM+ 的 chunk

### `render.js` 改动

* 可见范围按 chunk 迭代：`cx0..cx1, cy0..cy1`，每个 chunk 调 `drawChunk(c, ...)`

* `drawChunk` 内部按 chunk 局部坐标画 ground/obj，邻位查询用 `tileObjAt(ws, x+dx, y+dy)`

* 未持有 chunk（VIRGIN）画雾色占位

* 小地图改为滑动窗口：以相机为中心 ±16 chunk，每 chunk 一个色块

### `game.js` 改动

* `serialize()`：不再存 `Array.from(world.ground)`，改存 `serializeChunks(world.ws)`（只存非 VIRGIN 的）

* `hydrate()`：`genWorld(seed)` 重建起源 4 chunk → `hydrateChunks(ws, data.chunks)` 覆盖

* `v1→v2` 迁移：旧档无 chunks 字段但有 `world.ground/obj` 72×72 数组，拆分到 4 个起源 chunk

* 主循环新增 `updateChunkStates()`：根据 NPC 位置和视野标记 HOT，邻接标 WARM，超时降级

* 分层 tick：`hourChanged` 时跑 `forEachWarm` → `tickChunkWarm`；`dayChanged` 时跑 `forEachCool` → `tickChunkCool`

### `npc.js` 改动

* `setGoto` 加守卫：目标 chunk 未生成时先 `ws.ensure` 再寻路

* 寻路分段：长路径（跨 chunk）分 48 步段，抵达段末自动续程

### `ui.js` / `boot.js` 改动

* `jumpCam` 去掉 `[-4, 72-vw+4]` 钳制，改为 `ws.ensure` 目标周围 3×3 chunk

* `clampCam` 改为软限：不离最近 NPC 超过 32 chunk

* 小地图点击：基于相机中心的滑动窗口坐标

### 新增 selftest 阶段 33-36

* 阶段33 区块生成确定性（同种子同 chunk 一致 / 不同 chunk 不同 / 起源 4 chunk 城镇完整）

* 阶段34 跨区块寻路（同 chunk 内 / 跨 chunk / 远距离分段）

* 阶段35 冷热状态转换（VIRGIN→COLD→WARM→HOT→WARM→COOL→COLD 链路）

* 阶段36 存档只存热区块 + v1 旧档迁移

## 第三步：虚假记忆（v2.3.0）

### `memory.js` 改动

新增第五类记忆——虚假记忆（confabulation）：

```js
// 记忆条目新增字段: synthetic: true（标记为虚假记忆，但不影响 recall 行为）
// 虚假记忆的 orig 是传闻文本而非真实事件，但 NPC 对待它跟真实记忆一模一样

export function confabulate(npc, text, day, hour, mood, source) {
  // source: 'rumor'（听传闻后坚信自己在场）/ 'isolation'（孤独时编造陪伴）/ 'suggestion'（被暗示）
  const mem = makeMemory(text, day, hour, mood);
  mem.synthetic = true;
  mem.confabSource = source;
  npc.memories.push(mem);
  if (npc.memories.length > 40) npc.memories.shift();
}
```

**触发条件**：

* **传闻植入**：NPC 听到一条 gen>=2 的传闻（`recordRumor` 里 `gen >= 2`），有概率（心情越低概率越高，base 8% + (50-mood)\*0.3%）把传闻内容变成自己的"记忆"——"我当时在场"

* **孤独编造**：NPC 社交孤立（连续 3 天没有聊天记录），有概率生成"有人来看过我"的虚假记忆

* **暗示**：被 AI 决策中的 `say` 内容暗示后（"你忘了那天的事？"），有概率植入

**与历史系统的交叉验证**：

* 虚假记忆在编年史里找不到对应条目——这是玩家发现"这段记忆是假的"的唯一途径

* `fleshOf` 不返回虚假记忆（故者不会把虚假记忆当血肉输出，因为系统知道它是假的，但 NPC 不知道）

* `recentMemories` 正常输出虚假记忆（NPC 不知道自己是假的）

### `secret.js` / `npc.js` 接线

* `recordRumor` 返回后，在 `gossip` 的听者侧调 `maybeConfabulate(listener, rumorText, mood)`

* `tryPairChat` 结束后检查双方聊天孤立度

* NPC tick 里检查 `daysSinceLastChat`，超 3 天触发孤独编造

### 新增 selftest 阶段 38

* 虚假记忆植入（rumor 触发 / 孤独触发）

* 虚假记忆走 recall 正常漂移

* 虚假记忆在 fleshOf 中不出现

* 虚假记忆在 recentMemories 中正常出现
